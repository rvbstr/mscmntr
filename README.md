# Арт-календарь Москвы

Русскоязычный редакционный индекс современного искусства: афиша, календарь, каталог пространств и открытый журнал источников. React + TypeScript + Vite, статические JSON, Python-сборщик и GitHub Pages. Постоянный сервер и платная база не нужны.

## Локальный запуск

Нужны Node.js 24, npm и Python 3.12. В уже изолированной cloud-задаче используйте существующий checkout `/workspace/mscmntr`; создавать Git worktree не требуется.

```sh
npm ci --cache /workspace/.cache/npm
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
npm run dev -- --port 5173
```

На обычной локальной машине параметр `--cache /workspace/.cache/npm` можно опустить. Для команд Python активируйте `.venv` (`source .venv/bin/activate`) или используйте `.venv/bin/python` явно. На Windows: `.venv\Scripts\python`.

```sh
.venv/bin/python -m ingestion.import_catalog
.venv/bin/python -m ingestion.run
npm run build
npm run preview
```

Импорт не запускает сканирование. Полный сбор последовательно обрабатывает источники, соблюдает robots.txt, интервалы между запросами и таймауты; он может занять несколько минут. Никакой сбор не выполняется из браузера.

## Настоящий каталог и его импорт

Исходники пользователя сохранены как `catalog/original.json` и `catalog/original.xlsx`. Это 93 записи (74 monitor, 5 watchlist, 7 excluded, 7 discovery), 143 уникальных источника, 164 связи институций с источниками, 19 алиасов и 22 тега. Все исходные ID, URL, роли, алиасы и отношения сохраняются. ZIP не требовался: оба исходных файла доступны.

```sh
.venv/bin/python -m ingestion.import_catalog --json catalog/original.json --xlsx catalog/original.xlsx
```

Импорт проверяет дубли ID, ссылки и согласованность JSON/XLSX. `catalog/normalized.json` сохраняет все 11 таблиц XLSX, включая announcements и event_evidence; `catalog/catalog.json` содержит объединённый каталог; `public/data/catalog.json` — каталог для сайта. Встроенные примеры событий остаются кандидатами, а не автоматически опубликованными анонсами.

JSON без XLSX тоже поддерживается: укажите несуществующий `--xlsx` либо удалите необязательный workbook. В этом режиме сохраняются все вложенные данные JSON; дополнительные плоские таблицы XLSX недоступны. Если нет каталога, интерфейс показывает ошибку отсутствующих данных, сборщик завершает работу с понятной инструкцией. Импортер ничего не выдумывает.

Для добавления или удаления институции обновите исходный JSON (и соответствующие таблицы XLSX, если он используется), сохраняя стабильные ID и связи. Повторите импорт, сбор и проверки. Для временного исключения площадки используйте `monitor_state`; источники и сама запись остаются в каталоге. Чтобы только отключить запросы к сломанной странице, используйте `disabled_sources`.

Категория независимой сцены выводится из исходных тегов `artist_run` и `independent`. Районы не угадываются по адресам: в предоставленной базе их нет. Поле `district` в location включит соответствующий фильтр после импорта. Исходные неподтверждённые адреса обозначены в досье. Приоритет `A/B/C` преобразуется в `high/normal/low`; он влияет на очередь обхода, а афиша всегда сортируется по датам или обнаружению.

## Сборщик

```sh
.venv/bin/python -m ingestion.run                         # принудительная проверка
.venv/bin/python -m ingestion.run --scheduled             # только если прошло 72 часа
.venv/bin/python -m ingestion.run --source SRC_E4BBF3E60D4929 --max-pages 3
```

Методы: публичные Телеграм-посты, официальный Instagram Graph API при разрешённом доступе, импорт локальных экспортов Instaloader в очередь проверки; RSS/Atom с явной датой события в тексте; schema.org Event / JSON-LD; встроенные адаптеры публичного состояния ГЭС-2 и отдельных страниц «Пространства пространств» и КУБ; осторожный HTML-парсер по заданным селекторам. Порядок исключает смешивание противоречащих структурированных и резервных HTML-данных. Для карточек ГЭС-2 используются даты самих сеансов, выставочные интервалы хранятся отдельно. Повторяющиеся сеансы с разным временем не объединяются.

HTML-парсер принимает только отдельное announcement article с заголовком и собственным блоком даты. Он не извлекает произвольные даты из всего сайта. Год должен присутствовать в датированном анонсе либо быть явно указан редактором в правиле. Недатированный текст и неоднозначная привязка общего сайта к нескольким институциям уходят в очередь проверки.

Дополнительные правила задаются в `editorial/overrides.json`, `parser_rules`, по `source_id` или hostname:

```json
{
  "SRC_СУЩЕСТВУЮЩИЙ_ID": {
    "root": "article.exhibition",
    "title": "h1",
    "dates": ".exhibition-dates",
    "description": ".description",
    "event_type": "exhibition"
  }
}
```

Для нестандартной структуры добавьте модуль в `ingestion/adapters/`, подключите его и сохраните ограниченный реальный HTML-снимок с provenance для теста. Структурированные даты должны описывать событие, а не публикацию, обновление сайта или копирайт.

Сборщик проверяет robots.txt до чтения страницы, не обходит логины/CAPTCHA и ограничения платформ, использует подтверждённый TLS, задержки по хостам, таймауты, ограничение ответа 2 МБ и повтор временных ошибок с backoff. Изображения и видео не загружаются. Приватные адреса и credential URLs отвергаются. Ошибки соединений редактируются перед сохранением; значения секретов не попадают в отчёт.

Доступность ссылки — отдельная проверка. Ограничение прокси/авторизации не считается 404. Событие должно иметь отдельную оригинальную ссылку; общая главная страница и профиль соцсети недостаточны. Неуверенные результаты не публикуются. Ранее подтверждённые события сохраняются при частичных сбоях.

Результаты:

- `public/data/events.json`: события, evidence, время фактического обновления, состояния всех 143 источников;
- `public/data/review.json`: очередь проверки без вымышленных событий;
- `public/data/report.json`: сводка последнего запуска.

Выход 0 — завершённый или пропущенный по расписанию запуск; 2 — ни одна страница не прочитана либо отсутствует каталог. Необработанная ошибка/конфликт правок — ошибка запуска, прежний events.json остаётся нетронутым. JSON записывается атомарно. При полном отказе сети прежние события и время успешного обновления сохраняются, обновляется журнал ошибок.

## Редакторские правки

`editorial/overrides.json` валидируется через `overrides.schema.json`, включая форматы дат и ссылок. Он не перезаписывается при сборе.

- `manual_events`: вручную добавленные события. Обязательны стабильный event_id, institution_id, title, event_type, start_date, primary_url. Дата `YYYY-MM-DD`, время `HH:MM`, зона Europe/Moscow.
- `corrections`: словарь event_id → исправленные поля (заголовок, даты, время, тип, URL, адрес, описание).
- `suppress`: ID ложных срабатываний, которые не должны публиковаться.
- `duplicates`: ID дубликата → ID основной записи; evidence объединяется. Циклы, конфликт скрытия/объединения и отсутствующий основной ID — ошибка. Уже объединённый ID дубликата повторно удалять не нужно: правка идемпотентна.
- `priorities`: institution_id → `high`, `normal` или `low`.
- `disabled_sources`: ID источников, которые нужно сохранить в каталоге, прекратив автоматические запросы.

Полный пример элемента `manual_events` (шаблон, не реальное событие):

```json
{
  "event_id": "EDITORIAL_STABLE_ID",
  "institution_id": "СУЩЕСТВУЮЩИЙ_ID",
  "title": "Точное название из анонса",
  "event_type": "opening",
  "start_date": "2026-10-24",
  "start_time": "18:00",
  "primary_url": "https://institution.example/events/exact-announcement"
}
```

Ручная запись проверяется по отдельной ссылке. Если редактор сам подтвердил оригинальную публикацию, но автоматический доступ ограничен, можно добавить `editor_verified_at` с ISO timestamp и зоной: это явная редакционная верификация; недоступность автоматической проверки отображается отдельно. Не используйте это поле для обхода проверки фактов. Ни один пример из документации не импортируется автоматически.

## Сайт и персональные функции

Четыре раздела: Афиша, Календарь (месяц/неделя), все 93 пространства, журнал источников. Интерфейс чёрно-белый, переключаемая светлая/тёмная тема сохраняется локально и по умолчанию следует системной. Типографика ориентируется на опубликованные CSS garagemca.org: основной текст 20 px, заголовки событий 28–34 px, основной заголовок до 66 px. Рекламные блоки и отдельный логотип удалены. Москва — география по умолчанию; явно региональные анонсы доступны отдельным фильтром. Поиск понимает русские/латинские названия и исходные алиасы. Фильтры совмещаются и сохраняются в URL. Под сообщением об охвате на каждой странице отображаются выбранные фильтры: каждый можно снять отдельно или нажать «Сбросить фильтры». Статусы в каталоге и журнале источников также имеют отдельные снимаемые теги. Независимые пространства выбираются через фильтр; отдельного рекламного блока нет. Все даты и текущий день — по Москве; неделя начинается с понедельника. Ссылки `?event=ID` и `?space=ID` работают при прямой загрузке на GitHub Pages, без history router.

Сердце сохраняет пространство, закладка — событие. Личный архив, просмотренные события и прошлое посещение хранятся в localStorage, при запрете storage работают в рамках текущего сеанса. События, найденные после предыдущего визита, отмечены. В досье события — исходный анонс, все evidence, ссылка для обмена и скачивание корректного `.ics`. HTML источника не рендерится: описания извлекаются в обычный текст, React его экранирует, URL ограничены HTTP(S).

«Обновить данные» повторно запрашивает опубликованный JSON с cache-busting и не сканирует источники. «Запустить проверку источников» открывает GitHub Actions для владельца. Браузер не получает GitHub API credentials. Архитектура необязательного авторизованного serverless-trigger: [docs/optional-trigger.md](docs/optional-trigger.md).

## Проверки

```sh
.venv/bin/python -m pytest tests -q
npm test
npm run build
npm run dev -- --port 5173
# В другом терминале, с установленным Chromium:
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npx playwright test
```

Для Playwright на обычной машине: `npx playwright install chromium`, затем `npx playwright test`. Внешний браузер не является зависимостью production-сайта. Браузерная проверка ожидает хотя бы одно реальное опубликованное событие, а не подменяет feed фикстурой. Python-тесты отдельно проверяют даты, сеансы, дедупликацию, импорт, прямые ссылки, 72 часа через границу месяцев, сохранение прежних данных при сбое, настоящие HTML-снимки и редакторские правки. Vitest проверяет поиск, совмещённые фильтры, московское время и ICS.

## Публикация на GitHub Pages

1. Сохраните изменения в Git и отправьте в `main` репозитория `rvbstr/mscmntr`.
2. В **Settings → Pages → Build and deployment → Source** выберите **GitHub Actions**.
3. В **Settings → Actions → General** разрешите workflow записывать данные в репозиторий. Если `main` защищён, разрешите Actions bot обновлять `public/data` либо адаптируйте шаг записи под pull request. Не отключайте защиту ветки без необходимости.
4. Откройте **Actions → Проверка источников и публикация → Run workflow → main**. Дождитесь успешных `build` и `deploy`. Ссылка опубликованного сайта появится в environment `github-pages`.

Workflow запускается при push, вручную и ежедневно в 07:17 UTC (10:17 МСК). Плановый запуск проверяет **72 часа после завершённого сбора**, а не `*/3` день месяца. Ручной запуск всегда обходит eligibility. Время GitHub Actions может сдвигаться; интерфейс показывает фактический результат.

Push собирает уже опубликованные данные; расписание и Run workflow дополнительно собирают источники. Данные коммитятся и сайт развёртывается **в том же workflow**: новый workflow от коммита `GITHUB_TOKEN` не предполагается. Результаты частичного отказа сети тоже публикуются с сохранением прежних событий. Ошибка схемы правок останавливает публикацию вместо ложного успеха.

Vite получает base_path от `actions/configure-pages`; локально его можно проверить командами `VITE_BASE_PATH=/mscmntr/ npm run build` и `VITE_BASE_PATH=/mscmntr/ npm run preview`. JSON, шрифты, favicon и ссылки с query-параметрами учитывают подкаталог. Для другого репозитория измените `src/config.ts`, зафиксированную ветку в workflow и адрес User-Agent в `ingestion/http.py`.

## Текущий охват и ограничения

Парсеры публичных программ, причины пропуска лекций и оценка ScrapeGraphAI: [docs/scraping.md](docs/scraping.md).

Последнее точечное обновление программ: [docs/source-coverage-2026-10-17.md](docs/source-coverage-2026-10-17.md).

Сводка первоначальной проверки и обновления социальных источников: [docs/source-coverage-2026-10-16.md](docs/source-coverage-2026-10-16.md).

Полный фактический отчёт хранится в `public/data/report.json`, детализация каждого источника — в `public/data/events.json` и на странице «Источники». «Страница доступна» не равнозначно «событие извлечено»: сайты без надёжного адаптера имеют статус «Частично». «Работает» означает извлечение проверенных событий без ошибок на проверенной части страниц; при неполном извлечении указан статус «Частично». Указанные статусы — результат последнего запуска, не обещание будущей доступности.

Публичные Телеграм-ленты читаются автоматически; дополнительно поддерживается авторизованный Telethon API. Для Инстаграма реализованы официальный Graph API и импорт разрешённых локальных экспортов Instaloader в очередь проверки. VK и linkhub пока требуют ручной проверки. Для Instagram API нужны секрет и переменные Actions — см. [docs/social-sources.md](docs/social-sources.md). Источники без доступа не помечаются как успешно проверенные. Независимые инициативы, в том числе Иваний, Девятнадцать, ДНИ, VIDEO VIOLENCE, Корней, Пространство пространств и NNFN, остаются доступны независимо от числа анонсов. Архивные и поисковые записи не обходятся автоматически.

Для публичных Телеграм-лент и сайтов секреты не нужны; Instagram API и необязательный Telethon требуют авторизованных credentials из настроек Actions; CI использует встроенный `GITHUB_TOKEN`. Сайты с авторизацией не становятся обязательными зависимостями. В cloud-среде нужны egress-домены исходного каталога (их список сохранён в черновике сетевых настроек); политика GitHub-hosted runner отличается, поэтому охват нужно проверять по его реальным отчётам. Расписание и production deployment подготовлены, но не считаются проверенными до запуска workflow в вашем GitHub.
