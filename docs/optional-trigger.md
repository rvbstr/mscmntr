# Необязательная кнопка запуска с сайта

Базовая реализация работает бесплатно на GitHub Pages: ссылка владельцу открывает `refresh-deploy.yml`, где `workflow_dispatch` запускается авторизованным участником репозитория. Посетители повторно загружают только опубликованный JSON. Секретов и обращений к GitHub API в браузере нет.

Для будущей кнопки без перехода на GitHub достаточно Cloudflare Worker на бесплатном тарифе. Этот модуль не требуется для публикации и пока не развёрнут.

Контракт будущего endpoint:

1. `POST /refresh`, фиксированные репозиторий `rvbstr/mscmntr`, workflow `refresh-deploy.yml`, ref `main`. Не принимать целевые репозитории, ref, URL или токены от посетителя.
2. Перед Worker — Cloudflare Access с разрешёнными аккаунтами владельцев. Worker проверяет подпись JWT из `Cf-Access-Jwt-Assertion` по JWKS команды, issuer, audience, expiration. Одной проверки наличия заголовка недостаточно.
3. Проверять точный Origin опубликованного сайта, использовать POST с CSRF-защитой, не разрешать `Access-Control-Allow-Origin: *` вместе с авторизацией. Сессия должна быть `Secure`, `HttpOnly` и с подходящим SameSite.
4. Ограничивать частоту по авторизованному пользователю (например, один запуск за 5 минут); блокировку хранить в Durable Object. Неподтверждённый запрос не должен доходить до API GitHub.
5. Worker получает краткоживущий installation token GitHub App с минимальными Actions write и Metadata read для одного репозитория. Ключ App хранится исключительно в Worker Secrets; не использовать долгоживущий пользовательский токен в клиенте.
6. Сервер делает `POST https://api.github.com/repos/rvbstr/mscmntr/actions/workflows/refresh-deploy.yml/dispatches` с `{"ref":"main"}`. Только реальный 204 означает «Запуск запрошен». Это не означает завершённый сбор. На ошибки API возвращать понятный статус, не раскрывая credential headers.
7. После 202/204 интерфейс показывает ссылку на журнал Actions. Время данных меняется только после загрузки новой опубликованной версии JSON. Не рисовать сообщение об успешном обновлении источников при одной лишь отправке dispatch.

Настройка, проверка JWT и развёртывание интеграции — отдельная необязательная работа. Текущий сайт не зависит от её доступности.
