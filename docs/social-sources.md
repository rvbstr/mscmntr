# Телеграм и Инстаграм: сбор и разрешённый доступ

## Что работает без секретов

Телеграм-адаптер читает публичные ленты `https://t.me/s/<channel>` через Requests + Beautiful Soup. Сохраняются текст отдельного поста, точная ссылка `https://t.me/<channel>/<message_id>` и timestamp публикации. По умолчанию читаются две страницы публичной ленты, до 40 текстовых постов на канал; изображения и видео не скачиваются. Запросы ограничены по частоте, robots.txt фиксируется в журнале, действует общий таймаут. Закрытые каналы, приглашения и перенаправленные чужие анонсы не используются для автоматической атрибуции.

```sh
.venv/bin/python -m ingestion.run --source SRC_A7A55D3F520E67 --social-posts 20 --max-pages 0
```

Проверяйте ID по `catalog/catalog.json`: приведённый ID — основной Телеграм-источник IVANY из предоставленного каталога. Параметр `--social-posts` допускает от 1 до 50; публичная страница может содержать меньше постов. Это ограниченный срез последних публикаций, а не весь архив.

Сначала парсер выделяет собственный заголовок события и блок дат. Год без явного указания разрешается только по timestamp **этого же поста** с ограниченным окном — от 14 дней до публикации до 180 дней после неё. Это явно отмечается в данных и досье. Даты из биографий не используются. Несколько независимых дат, неясное название, чужой город и недоступная ссылка отправляются в редакционную очередь.

Москва показывается по умолчанию. Публикации с явным адресом в Балашихе маркируются `moscow_region` и доступны через фильтр «География → Подмосковье» или «Москва и Подмосковье». Они не подмешиваются в московскую афишу. Публикации о событиях в других городах остаются в очереди проверки.

## Необязательный Telethon

[Telethon](https://docs.telethon.dev/) — открытая библиотека официального Telegram MTProto API. Если публичный веб-просмотр недоступен, владелец может отдельно настроить разрешённую, уже авторизованную сессию. Сборщик не запрашивает телефон, коды входа или 2FA и не делает интерактивный login в Actions.

В GitHub **Settings → Secrets and variables → Actions**:

| Тип | Имя | Назначение |
| --- | --- | --- |
| Variable | `TELEGRAM_MODE` | `api` включает Telethon; по умолчанию `preview` |
| Variable | `TELEGRAM_API_ID` | ID приложения, полученный у Telegram |
| Secret | `TELEGRAM_API_HASH` | Ключ приложения |
| Secret | `TELEGRAM_SESSION` | Уже авторизованная StringSession владельца |

Получение собственной сессии выполняйте отдельно по документации Telethon. Не публикуйте строку сессии, не добавляйте её в репозиторий и не присылайте в чат. На `FloodWait` сбор прекращается без обхода ограничения. Сетевой доступ к MTProto должен быть разрешён в runner; HTTP-прокси cloud-среды может его не поддерживать. В текущей проверке Telethon без учётных данных не запускался: проверен публичный веб-транспорт.

## Instagram: официальный API

В [robots.txt Instagram](https://www.instagram.com/robots.txt) прямо указано ограничение автоматизированного сбора без разрешения платформы. Поэтому анонимный обход профилей, подмена браузера, cookies для обхода ограничений и сторонние неофициальные зеркала не реализованы. Наличие библиотеки не отменяет правил доступа.

Для актуального автоматического сбора реализован официальный Graph API:

- `business_discovery` — чтение доступных профессиональных аккаунтов через `graph.facebook.com`. Нужны профессиональная Instagram-учётная запись, связанная с Facebook Page, разрешённое Meta-приложение и токен с действующими разрешениями Business Discovery. Возможности чтения чужих профилей определяются разрешениями приложения и типом профиля.
- `own_account` — `graph.instagram.com/<account_id>/media`, только для собственной авторизованной профессиональной учётной записи. Токен одного владельца не даёт произвольный доступ к чужим аккаунтам.

В **Settings → Secrets and variables → Actions** задайте:

| Тип | Имя | Назначение |
| --- | --- | --- |
| Secret | `INSTAGRAM_ACCESS_TOKEN` | Разрешённый токен Meta/Instagram; никогда не в frontend |
| Variable | `INSTAGRAM_ACCOUNT_ID` | Числовой ID авторизованного профессионального аккаунта |
| Variable | `INSTAGRAM_API_MODE` | `business_discovery` (по умолчанию) либо `own_account` |
| Variable | `INSTAGRAM_ACCOUNT_USERNAME` | Нужен в режиме `own_account`, без `@` |
| Variable | `INSTAGRAM_GRAPH_VERSION` | По умолчанию `v24.0`; можно выбрать поддерживаемую версию приложения |

Ориентируйтесь на актуальные [Instagram Platform](https://developers.facebook.com/docs/instagram-platform/) и [Business Discovery](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-facebook-login/business-discovery). Не выдавайте приложению дополнительные права ради обхода недоступного профиля. Если Meta требует app review, advanced access или не даёт доступ к типу аккаунта, источник останется «Требует настройки доступа».

Токен передаётся в HTTP Authorization header, не в URL, опубликованных данных или логах. Подробные ответы об авторизации редактируются перед сохранением. На 429 и лимиты Meta повторов нет; временные 5xx повторяются ограниченно. Данные поста берутся из API: caption, permalink, timestamp. Полученный API permalink служит evidence; отдельный анонимный скрейпинг страницы не выполняется.

В cloud-машине на момент реализации этих переменных не было, поэтому live-сбор Instagram через API **не подтверждён**. Проверены формат запроса, разбор ответа, ограничение собственной учётной записи, обработка отказов и сохранность токена с тестовым транспортом. Для фактической проверки добавьте учётные данные безопасно в настройки Actions и запустите workflow.

## Instaloader: импорт разрешённых локальных экспортов

[Instaloader](https://instaloader.github.io/) включён как открытая библиотека для чтения его сериализованных Post-экспортов. При наличии законного разрешённого экспорта положите `.json` или `.json.xz` в:

```text
.local/instagram/<username>/<post>.json
```

```sh
.venv/bin/python -m ingestion.run --instagram-export-dir .local/instagram --source <SOURCE_ID>
```

Папка `.local/`, сессии и служебные файлы не коммитятся. Проверяется owner username, shortcode, дата и подпись. При неполных полях скрытое сетевое дополнение заблокировано. Учётные данные и сессия Instaloader не загружаются. Прочитанные кандидаты направляются в `public/data/review.json`: локальный файл не является свежей проверкой доступности ссылки. После ручного подтверждения редактор может добавить событие через `manual_events` с `editor_verified_at` и точной ссылкой.

Если настроен официальный API, он имеет приоритет над локальным экспортом. Экспорты и фикстуры тестов никогда автоматически не подменяют живую production-ленту.

## Контроль качества и логи

Для социальных источников журнал содержит `adapter`, `posts_seen`, число подтверждённых событий и последнюю ошибку. Статус «Частично» означает, что лента прочитана, но некоторые кандидаты требуют проверки. Недоступный preview, отсутствие API credentials и реальный пустой ответ различаются. Ошибка одного канала не прерывает другие источники и не удаляет ранее подтверждённые события.

## Поиск и добавление Telegram-каналов

Новые каналы хранятся отдельным дополнением `catalog/additional-sources.json` с принадлежностью площадке, evidence и реальным временем проверки. Оригинальные файлы пользователя не редактируются. Инструмент поиска создаёт кандидатов; он не назначает их площадкам автоматически:

```sh
.venv/bin/python -m ingestion.discover_telegram --workers 6 --max-pages 4
.venv/bin/python -m ingestion.discover_telegram --verify-only
```

Локальные снимки и отчёты остаются в игнорируемой `.local/discovery/`. Повторный запуск использует их фактические timestamps; для новых сетевых проверок добавьте `--refresh`. Рабочий сборщик `ingestion.run` всегда использует свой HTTP-клиент и не подменяет живую ленту этими снимками. Ссылки на ботов, приглашения, личные контакты, вакансии и чужие площадки не становятся источниками институции только потому, что найдены на её сайте.

После редакционной привязки и добавления evidence выполните `python -m ingestion.import_catalog`. Флаг `requires_identity_confirmation` допускает чтение постов только в очередь проверки; `requires_location_confirmation` требует явного указания Москвы/Подмосковья; `collection_enabled: false` сохраняет архивный источник без автоматических запросов. Общие каналы школ имеют роль `secondary_discovery`, чтобы не приписывать все их события конкретной галерее. У поисковых сетей и исключённых институций прежний режим мониторинга сохраняется.

## Анонсы и регистрация по ссылкам из Telegram

После чтения живого Telegram-поста сборщик проверяет до двух внешних ссылок из его текста и при необходимости одну ссылку регистрации со страницы анонса. Общий предел — три страницы на пост и 12 новых страниц на канал за запуск; повторные URL кешируются. UTM-метки удаляются. Лента другого канала, главная страница, раздел афиши и файлы не считаются отдельными анонсами. Используется тот же HTTP-клиент с таймаутами и проверкой публичных адресов.

Из связанной страницы читаются JSON-LD, разметка институции, встроенное состояние или текст статьи. Название сопоставляется с постом, дата — с датами анонса. Год при его отсутствии может уточняться по контексту поста; дата публикации статьи не становится датой мероприятия. Страница ВШЭ `/news/7306`, например, даёт название презентации альбома «алеа», расписание 20:00–23:00 и адрес «Склада №3».

Подтверждённый анонс становится основной ссылкой карточки; Telegram-пост остаётся в evidence. Для отдельной страницы регистрации появляется кнопка «Регистрация». Площадка и её связь с каталогом проверяются отдельно: точный адрес не подтверждает принадлежность события галерее, которой сопоставлен общий канал. Если сайт недоступен, даты расходятся или название не связано с постом, сохраняется исходный результат. Обработанные ссылки и причины отказа находятся в `linked_pages` и `linked_page_issues` журнала источника. Сбор не отправляет формы и не регистрирует посетителя.
